# Prior Art

Rule: hand-write only what a trusted existing implementation (library, OSS solving the same problem, standard) cannot
cover. A check that judges another language or format is built on what that language's own parser returns; hand-written
text analysis covers only what no parser reports. Security-sensitive parsing prefers an established library; where we hand-write, we test against existing test
vectors. Every dependency adds supply-chain cost, so a library is adopted only when it clearly beats a small
hand-written piece on correctness. Status checked 2026-11 (latest version on proxy.golang.org, licence and last push on
GitHub). Section numbers refer to `docs/design/phase2-core.md`.

| Mechanism | Candidates compared | Decision | Reason |
|---|---|---|---|
| TOML config (§2.1, §3) | [`BurntSushi/toml`](https://pkg.go.dev/github.com/BurntSushi/toml) v1.6.0 (MIT); [`pelletier/go-toml/v2`](https://pkg.go.dev/github.com/pelletier/go-toml/v2) v2.4.3 (MIT) | Keep BurntSushi | Both TOML 1.0, maintained and report error positions (`ParseError`; Pelletier's `DecodeError.Position()`); only BurntSushi exposes `MetaData.Keys()` in file order (unknown-key warnings, `[handover]` order), with no dependencies. |
| Bash parsing (§3, §4.3) | [`mvdan.cc/sh/v3/syntax`](https://pkg.go.dev/mvdan.cc/sh/v3/syntax) v3.14.1 (BSD-3); legacy regex split | Keep mvdan.cc/sh | The `shfmt` parser is the de facto Go bash parser; `syntax` imports no third-party packages. A regex split cannot see quotes, heredocs or `$(…)`. |
| `.kits` file lock (§3) | [`gofrs/flock`](https://pkg.go.dev/github.com/gofrs/flock) v0.13.2 (BSD-3); hand-rolled `flock(2)`/`LockFileEx` | Keep gofrs/flock | One portable API over both OS calls; only runtime dependency is `golang.org/x/sys`, which hand-rolled `LockFileEx` would need anyway. |
| `stack` CLI flags (§3) | stdlib `flag` + `parseInterspersed` (`internal/cli/flags.go`, 74 lines); [`spf13/pflag`](https://pkg.go.dev/github.com/spf13/pflag) v1.1.0 (BSD-3, no deps); [`spf13/cobra`](https://pkg.go.dev/github.com/spf13/cobra) (Apache-2.0) | Keep stdlib `flag` for now; revisit after PR 4 | Alone, pflag would only replace a small, tested helper. Once `ghargs` makes it a dependency, it would handle flags after positionals and `--` natively; switching `internal/cli` is a separate refactor decided after PR 4. Cobra is too much for seven commands. |
| GraphQL merge detection in `gh api graphql` (§4.3 raw merge) | hand-written lexer that scans the whole document; [`vektah/gqlparser/v2/parser`](https://pkg.go.dev/github.com/vektah/gqlparser/v2/parser) v2.5.64 (MIT, used by gqlgen); [`graph-gophers/graphql-go`](https://github.com/graph-gophers/graphql-go) (BSD-2, server, needs a schema); [`graphql-go/graphql`](https://github.com/graphql-go/graphql) v0.8.1 (MIT, no deps; `language/parser` parses without a schema) | Adopt gqlparser `parser` (no schema, no validator) | `parser.ParseQuery` parses a document without a schema and keeps `Field.Alias` separate from `Field.Name`, with `Fragments` and inline fragments. Deny when a `mutation` operation's selection, following fragment spreads and inline fragments, has a field named (not aliased) `mergePullRequest`/`enablePullRequestAutoMerge`. This replaces hand-written handling of block strings, escapes, comments and aliases with a spec parser. The packages compiled in (`parser`, `lexer`, `ast`, `gqlerror`) import nothing outside the module; `levenshtein` and `yaml` are used only by the validator. graphql-go's standalone parser would also fit, but its last release is from 2023-04, while gqlparser is released regularly and backs gqlgen. Checked: alias, fragment and alias-named query cases parse as expected. A query gqlparser cannot parse is not judged (allowed), as a local decision: the rule guards the agent's own mistakes; that GitHub rejects the same documents is assumed, not verified. |
| Pencil `Generate(` detection in JS (§4.3 pencil) | hand-written lexer (strings, templates, comments); [`tdewolff/parse/v2/js`](https://pkg.go.dev/github.com/tdewolff/parse/v2/js) v2.25.0 (MIT, no runtime deps, used by `tdewolff/minify`); [`dop251/goja/parser`](https://pkg.go.dev/github.com/dop251/goja/parser) (MIT; module requires regexp2, yaml, pprof, …); esbuild (`internal/js_parser`, not importable) | Adopt tdewolff `js` | A hand lexer must also tell regex literals from division (`/"/; Generate()` hides the call from a lexer that only knows strings), which needs parser context. `js.Parse` + `js.Walk` finds `CallExpr` whose callee name (identifier or member property) starts with `generate`, case-insensitively, as legacy did and handles nested templates (`` `${`${Generate()}`}` ``). Checked: regex, division, string and nested-template cases correct. Top-level `return`/`await` must parse, so wrap the snippet in `(async function(){\n…\n})`. On a parse error, and for each `edits[].replace`, fall back to the `js.Lexer` token stream: deny on an identifier starting with `generate` followed by `(` outside string, template and comment tokens. The fallback is best-effort: `Lexer.Next` emits `/` as division and only the parser asks for `RegExp()` in expression context, so the fallback guesses regex from the previous token and can misread a regex after `)` as code. Pencil applies `edits` to a failed snippet the payload does not carry, so the patched code cannot be parsed; a replacement that closes a string, inserts a call and opens the next string passes (legacy denied it). goja is a whole runtime with heavy deps. |
| `gh` argv semantics (§4.3 `ghargs`) | hand-written pflag-like parser + flag table; import [`cli/cli/v2`](https://pkg.go.dev/github.com/cli/cli/v2) v2.105.0 (MIT) cobra commands; [`spf13/pflag`](https://pkg.go.dev/github.com/spf13/pflag) + hand-written flag table | Adopt pflag; hand-write the flag table; not cli/cli | gh parses argv with cobra/pflag, so pflag gives exact parity on combined shorthands, `-b=x`, `--name=<bool>`, a value flag taking a following `-x`, and `--`; checked `-db=/x/y -- --body z`. Importing cli/cli pulls in ~170 required modules and pins gh's flags to our version, not the installed gh. The table lists every flag of the covered commands as of gh v2.105.0 (name, shorthand, bool/value, repeatable; `gh api` `-f`/`-F` are `StringArray`, every value scanned), checked against that version's declarations in PR 4. A flag of a newer gh missing from the table stops pflag with an unknown-flag error; the call is then denied if an input collected so far has a hit, and otherwise the remaining words are scanned as literal text for local paths. |
| Local paths in public text (§4.5 `publictext`) | [gitleaks](https://github.com/gitleaks/gitleaks) / [betterleaks](https://github.com/betterleaks/betterleaks) rules (MIT); [trufflehog](https://github.com/trufflesecurity/trufflehog) (AGPL-3.0); legacy `public-check` | Hand-write | Secret scanners detect credentials and treat home paths only as allowlists (`betterleaks/internal/rulebuilder/global.go`); no library detects home-directory paths. Trufflehog's AGPL rules out reuse. Parity vectors: `dotfiles:tests/test_kaizen_public_check.py`, plus one case per Windows/Git Bash/WSL form. |
| Process runner (§2.2 `internal/proc`) | plain `os/exec` (`Cmd.Stdout/Stderr` writers + `WaitDelay`); own pipes + `os/exec` (`feat/hookio-proc`); [`go-cmd/cmd`](https://pkg.go.dev/github.com/go-cmd/cmd) v1.4.4 (MIT) | Keep own pipes | `os/exec` returns one error and reports `ErrWaitDelay` only when the run otherwise succeeded: `watchCtx` and `Wait` keep an earlier `ExitError` or `ctx.Err()`, and `awaitGoroutines` drops copy errors after a failed exit (Go 1.27 `src/os/exec/exec.go`, `watchCtx`, `Wait` ~936-971, `awaitGoroutines` ~981-1018). Checked: `sleep 5 & exit 3` → only `exit status 3`; a timeout kill with a held pipe → only `signal: killed`. §4.7 ignores the exit code when stdout is valid JSON, so an extension that exits non-zero while a grandchild holds the pipe would go unreported. go-cmd streams output but has no WaitDelay, no stdout cap and no overrun report. Minimal design: `os/exec` starts the child and kills it (`Cancel`, `WaitDelay` for a child that survives); stack creates the pipes, drains them in its own goroutines, and closes its ends `WaitDelay` after `Wait` returns (child exit observed, also after a timeout kill), recording the overrun as `WaitDelayExceeded` and a stderr forwarding error as `StderrErr`. |
| Fake executables in tests (§3, §8 `proctest`) | test-binary re-exec (`proctest`); stdlib helper-process pattern (`os/exec` tests, `GO_WANT_HELPER_PROCESS`); [`rogpeppe/go-internal/testscript`](https://pkg.go.dev/github.com/rogpeppe/go-internal/testscript) v1.16.0 (BSD-3) | Keep `proctest` | `testscript.Main` uses the same technique (copies the test binary into a `$PATH` dir, dispatches on `argv[0]`) but sets a process-wide `PATH` and has no per-path scenarios, call log or grandchild. The helper-process pattern needs the test to build the argv, but fakes are found by path (kit board, `.claude/merge-check`, `stack-<name>`) and must survive `Cmd.Env` replacement. Adopting either means a dependency or a rewrite for what proctest already does. |
| Git Bash path forms on Windows (§2.1) | MSYS2 `cygpath` (C, runtime tool); Go libraries | Hand-write in `internal/paths`; Windows details finished on Windows | No maintained Go library converts MSYS/Cygwin paths. Shelling out to `cygpath` adds a runtime dependency to hook latency. Rules follow MSYS2's conversion of `/` and `/<drive>`. |
| Hook JSON, transcript JSONL (§2.3) | `encoding/json` (+ `bufio.Scanner`/`json.Decoder`); `encoding/json/v2` | Stdlib `encoding/json` | Stable on the pinned toolchain; decode only the fields read, keep `tool_input` as `json.RawMessage`. |

Dependency updates: `.github/renovate.json` extends `github>shuymn/github-actions` (`default.json`), which sets a global
`minimumReleaseAge: "3 days"` on top of `config:best-practices`, so gomod updates also wait 3 days; only `digest`
updates of `shuymn/github-actions` itself are exempt. Minor/patch updates automerge except for `0.x` modules
(`gofrs/flock`).
